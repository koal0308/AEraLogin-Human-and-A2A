🧬 Human Identity

A cryptographically anchored human identity that serves as the ownership root for agents and applications.

Human layer

Soul-Bound Identity NFT

One non-transferable Identity NFT per wallet on BASE Mainnet, minted gasless. It is the human root of everything else on AEra.

Human layer

Wallet-signed ownership

Agents are registered, re-keyed and revoked by their owner with a wallet signature. The human stays in control of every agent they own.

Human layer

Login & gated access

AEra Login, OAuth for websites and NFT-gated communities continue to work exactly as before — for humans.

Human → AEra Identity → Agent ownership. A person proves they are human once and receives a Soul-Bound AEra Identity. That wallet can then own agents, and every change to an agent (registration, new key, rotation, revocation) needs a fresh signature from it. Websites integrate the human layer through the AEra Gate SDK and OAuth 2.0.

🤖 Agent Identity

Autonomous agents receive their own cryptographic identity instead of borrowing a human session.

Agent layer

Own identity, own keys

  • Stable agent identity
  • Ed25519 signing keys with key identifiers
  • Challenge–response verification
Agent layer

Lifecycle under owner control

  • Key rotation without changing the agent identity
  • Key revocation
  • Agent revocation
Agent layer

Agent Runtime

Agents run in their own runtime process. The private key is generated and kept there — AEra only ever receives the public key.

A human identity and an agent identity are not the same thing. An agent is owned by a human, but it authenticates with its own key — separate from the human login, OAuth and session layer.

🔁 Agent-to-Agent Communication

AEra agents are reachable through the AEra A2A Gateway, using the standard A2A protocol over JSON-RPC with a public Agent Card for discovery.

Gateway

Standard A2A interface

External A2A clients discover AEra agents through the Agent Card and send messages to the gateway. Every target agent is resolved from AEra's own records, not from what the caller claims.

Gateway

Replay protection

Every message identifier is accepted once. Duplicated or replayed requests are refused.

Gateway

Rate limiting

The gateway limits request volume before doing expensive work, so a single noisy caller cannot saturate it.

Agents can talk to other agents without every external peer being treated as an AEra-native agent. Reaching the gateway does not make traffic trusted, and it grants no permissions by itself.

🌐 Connect External Agents

External agents interact with AEra through the A2A gateway — and remain a separate trust domain from AEra-native agents.

External peer

AEra-issued peer credentials

Where configured, an agent owner can issue a credential to an external peer, and the gateway authenticates the peer with it.

  • Scoped to specific agents and skills
  • Expiring
  • Revocable, effective immediately
  • Bound to a stable peer identity across rotation
External peer

A peer is not an AEra agent

An authenticated external peer never becomes an AEra agent and cannot use peer credentials in place of an agent identity. Identity proves who is calling; authorization and scope decide what they may reach.

📈 Behaviour-Based Trust Assessment

Trust is earned through evidence. AEra observes the behaviour of authenticated external peers and derives a trust assessment from accumulated evidence.

Assessment

Derived, not declared

The assessment comes from what AEra itself observes and from relevant identity evidence — not from what a caller claims about itself. Trust fields sent by a caller are ignored.

Assessment

Level and confidence

A new peer starts as unknown. AEra separately tracks how much evidence it has, so “no information yet” is never confused with “well-behaved”.

Assessment

Survives credential rotation

The assessment belongs to the peer, not to a single credential, so rotating a credential does not reset or launder its history.

Trust assessment currently operates as an independent monitoring layer. It is not authentication and not authorization. It does not replace credential validation, scope checks, revocation, replay protection or rate limiting — and today it does not change any access decision.

🛡️ Principles

Separate identities

Humans, agents and external peers are distinct identities with no automatic escalation between them.

Separate credentials

Each layer has its own credentials. One layer's credential is never accepted by another.

Explicit authorization

Knowing who is calling is not permission. Access is scoped explicitly.

Cryptographic verification

Agents prove their identity with signatures, not shared passwords.

Observable trust

Trust is derived from evidence, never simply claimed.

Fail closed

When a check cannot be completed, the request is not promoted.

⚙️ How It Works

The complete user journey from signup to on-chain reputation

1. Wallet Connect & Signup

Users connect their wallet (MetaMask, Coinbase Wallet, WalletConnect). The system generates a challenge message that the user signs. No passwords, no emails - your wallet is your identity.

2. Identity NFT Minting (Gasless)

On first login, users automatically receive a Soul-Bound Identity NFT. Minting is completely gasless - users pay nothing! Gas costs are covered by our community through donations. The NFT is non-transferable and serves as permanent on-chain identity.

💙 Support the community: Help us onboard more users by donating to our community wallet

3. Social Interactions & Scoring

Users can follow others, share content, and engage. Each interaction increases the score in the database (instant) and is stored in the Registry Contract (on-chain verification).

4. Resonance Calculation

The Resonance Score combines Own Score with average Follower Scores. Creates a network effect: Creators with engaged followers have higher Resonance. Example: Own 54 + Avg Follower 66 = Total Resonance 120.

5. Automatic Blockchain Sync

A background process syncs scores to blockchain every 30 seconds. Milestone system: Sync occurs every 2 points (e.g. 50 → 52 → 54). Users see live status in dashboard: "✅ Synced" or "⏳ Pending (+X)".

6. Dashboard & Analytics

Users have access to a complete dashboard with: Follower list, NFT status, Blockchain Score comparison, Interaction history, and direct links to BaseScan for every transaction.

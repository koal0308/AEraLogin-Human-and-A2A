A2A Agent Card

The Agent Card is the public business card of the AEra A2A gateway. It is a small JSON document at a well-known address that tells other agents how to reach AEra agents, which skills are available and how callers can authenticate.

It follows the A2A protocol's discovery convention, so any A2A-compatible client can find it. The card is generated from the gateway's actual configuration every time it is requested: it never advertises a skill, capability or security requirement that the gateway does not really have.

⚙️ Capabilities

Optional A2A protocol features and whether the gateway supports them. The communication model is simple request/response: one message/send call, one reply.

–

🔐 Security

securitySchemes names the credentials the gateway understands. security lists the ones that are required; an empty list means anonymous calls are accepted and the credential is optional. The card reflects the gateway's current authentication policy.

–

Peer credentials are issued by AEra agent owners to named external peers. How peer credentials work →

🧰 Skills

Each skill corresponds to an existing AEra agent capability. agent.communicate is only listed while an agent runtime is reachable.

–

📖 Field reference

FieldMeaning
name, descriptionHuman-readable name and description of the gateway.
urlThe JSON-RPC endpoint to send requests to.
preferredTransportThe transport to use: JSONRPC.
protocolVersionThe A2A protocol version the gateway speaks.
versionVersion of the gateway itself.
providerThe organisation operating the gateway.
capabilitiesOptional protocol features (streaming, push notifications, state history).
defaultInputModes / defaultOutputModesAccepted and returned media types.
securitySchemes / securityUnderstood credentials, and which of them are required.
supportsAuthenticatedExtendedCardWhether a richer card is available to authenticated callers.
skillsWhat callers can ask for, with descriptions and examples.

🙈 What is deliberately not in the card

  • No trust information. AEra's internal trust assessment of external peers is never published.
  • No list of agents. Callers name a target agent themselves; the card does not enumerate AEra agents.
  • No secrets or internal details. Before it is served, the card passes a self-check against leaking anything that is not meant to be public.

🚀 Using the card

cURL
curl https://aeralogin.com/.well-known/agent-card.json

Point an A2A client at https://aeralogin.com. It reads the card, then sends message/send requests to the url from the card. Full request examples are in the A2A Gateway documentation.
